Settings

Settings is the one page where the user changes their profile, appearance, sign-in methods, devices, notifications, time format and GIF library. It opens from the status menu and from a few links in the app. Every change saves automatically. The page has no Save button.

Anatomy

  1. Frame. The same header and sidebar as a conversation. The title area shows a back arrow and "Settings".
  2. Page heading. "Settings", with a chip on the right and the line "Changes are saved automatically." For profile changes, the chip reads "Saving..." and then "Saved".
  3. Cards. One column of cards, at most 600 px wide, in this order: Profile, Appearance, Text Size, Login Link, Secret Code (only for an account that still has a code), Active Sessions, Install as App, Notifications on This Device (the heading names the device: iPhone, iPad, Phone or Computer), Allow / Mute Notifications, Time & Date, My GIFs, App version, and a collapsed DEBUG INFO card at the end.
  4. Notice. An amber notice above the heading, with a close control. It shows after "Sign out all other devices".

Rules

Page

ST-01Settings opens from "Settings" and "Notification settings" in the status menu. It also opens from "Manage your GIFs in Settings" in the GIF picker. The bot's messages refer to Settings by name. "Notification settings" and the picker link scroll to their sections. The section stays in view while the page fills, until the first tap, scroll or key press. A signed-out visit goes to the login page. Settings needs a connection.

ST-02Every control saves at once when its value changes. Profile text saves after a short pause in typing. It also saves when the user leaves the page, so no typed text is lost. A failed save shows "Could not save. Try again." next to the control.

ST-03On Settings, the sidebar and the header show live state, the same as on a conversation.

Profile

ST-04The avatar shows at 80 px with "Upload Picture" or "Change Picture". When a picture exists, "Remove" also shows. A picture can be any image up to 10 MB. The server crops the picture to a square. A rejected file shows "Choose an image up to 10 MB". Remove needs no confirmation.

ST-05Display Name holds up to 64 characters. Its placeholder is the username. Its hint says that the name can contain symbols and emoji. When Display Name is empty, the username is shown.

ST-06Bio holds up to 150 characters and has a live counter. Location holds up to 100 characters. Location has "Detect" when the server can find the country from the network address.

ST-07A profile change shows at once in the user's own header and on the user's messages. It also shows at once on the screens of other people.

Appearance and text size

ST-08Appearance shows a grid of theme cards. Each card has a preview, an accent dot and the name. The chosen card has a check badge. The themes are Discord Dark (the default), Midnight, Nord, Ocean, Sunset, Aurora, Terminal, Neon Glow, Tea House, Daylight and Solarized Light. A tap applies the theme to the whole app at once and saves it. When the saved theme no longer exists, the default theme applies.

ST-09Tea House changes its picture with the sun. Seven day pictures share the time from sunrise to sunset in equal parts, and five night pictures share the time from sunset to sunrise. Sunrise and sunset are those of the day and of the place: the city of the device's time zone (Copenhagen for Denmark, Nairobi for Kenya), with no location prompt. A time zone without a city (UTC) gets a fixed day from 06:00 to 20:00. From 3:00 to 3:59 a special picture shows, whatever the sun does.

ST-10Text Size has six presets: 14, 15, 16 (Default), 17, 18 and 20 px. Each preset shows as "Aa" at its size. A tap changes the size of all text at once and saves it. The account's other devices apply the theme and the text size at once.

Sign-in methods

ST-11Login Link starts with one line that summarises the sign-in methods of the account. The line is either "This account is tied to this device only." or the methods that the person has. The methods show in this order: login link, secret code, smart login.

ST-12With a link, the card shows the hint, the URL with its code masked, and Reveal and Copy. Then it shows "New Link", "Revoke" and the expiry choice. Without a link, the card shows the hint and "Create Login Link". The rules are on the sign-in page.

ST-13"Allow smart login" is a switch under the link. It shows only while the admin allows smart login. It is on by default.

ST-14Secret Code is below Login Link, and only for an account that still has a code. Why: the code is retired, and the login link does its job (AU-13). The card shows the masked code, Reveal and Copy, "New Code" and "Disable". Disable asks for a confirmation, because a disabled code cannot come back. After it, the card is gone and the status shows under Login Link. Status lines show for 3 seconds.

Devices

ST-15Active Sessions lists the account's connected devices. Each device has a phone or desktop icon, the network address and "Active {time}". The current device shows "This device" and is always listed. "Sign out all other devices" is always available, because a device can stay signed in without a connection. It is disabled during the first hour of the current device, with the text that says when it is available. It acts without a confirmation. After it, the page shows the notice "All other devices have been signed out." with the new secret code, when one exists.

ST-16Install as App shows "Install {name}" with its explanation. The explanation tells the person to open the app after the install and turn on notifications there. Inside the installed app, it shows "{name} is installed as an app on this {device}." instead. {name} is the server's name, which is also the name under the installed app's icon. See Offline and installation.

Notifications

ST-17The notifications card is named for the device: "Notifications on This iPhone", "This iPad", "This Phone" or "This Computer". Its text says what the person will see on this device when the app is closed, and nothing about push: a notification and a number on the app's icon for the installed app on a phone, a pop-up in the corner of the screen and a count in the tab title for a browser on a computer. A phone user reads that the phone treats the app like any other app, with its own entry under the phone's Settings. A browser on an iPhone or iPad cannot show notifications; the card says so and points to Install as App. The card shows the state of this device ("On", "Off", "Blocked", "Not possible here" or "Not set up on this server"), with a green check mark next to "On" and a red crossed bell next to every other state, the number of phones and computers that get notifications, and their list. Each entry has "Remove", and Remove on the entry marked "This device" turns notifications off here; there is no second button for that. The card shows "Turn on notifications on this {device}" only while this device is not in the list. When that is not possible, the card gives the reason. For a block, it gives the exact steps for this browser, or for the phone's Settings in the installed app. The card redraws when the person comes back to it, so a fix made in the phone's Settings shows at once. "Send a test to all my devices" shows when there are devices. The server's name stands in for "Yap" throughout. Why: the people who asked "why is my phone quiet" had installed the app and never found the switch behind "push" and "subscribe".

ST-18Allow / Mute Notifications starts with the server-wide "Allow" or "Mute" with a duration. Below it are the "Direct messages" and "Rooms" rows, each with "Allow", "Individual" and "Mute". In Individual mode, a row lists its conversations, each with a bell. The rules are on the notifications page. The mute hint reads "Muted for another {time}." with the correct singular form. The hint counts down while the page is open.

ST-27A red notice sits at the top of Allow / Mute Notifications when this device gets no notifications: they are off or blocked on this device, or this browser cannot show them. It says so in one sentence and links to the card above that has the switch or the fix. It goes away as soon as notifications are on here. Why: the rules below belong to the account. A person with a quiet phone would otherwise change the mutes and see no effect.

Time & Date

ST-19"Your time" shows the current time in the user's time zone, with "−", "+" and "Detect". Yap detects the zone at sign-up. The zone stays until the user changes it here. "−" and "+" move the shown time by one hour from its current value. The offset from universal time stays within 14 hours in either direction. After an adjustment, the zone is a fixed offset and daylight saving no longer applies. "Detect" takes the zone from the browser again. The language detected at sign-up sets the defaults below. The language has no control of its own.

ST-20Clock offers 24-hour and 12-hour. Date order offers day-month-year, month-day-year and year-month-day. Separators shows when the detected language and the country of the zone use different formats. Each of the three is a row of cards. Each card shows the current time or today's date in its form. The card that matches the language is first. Each row works with the keyboard. The choices apply to every time in the app.

My GIFs

ST-21My GIFs shows the user's pool: every starred GIF plus the user's own uploads, in folders. The toolbar has folder chips ("All", "Unsorted", one per folder), a filter field, "＋ Add GIFs", "Import zip" and "Export". The filter field shows when there are nine or more GIFs. A quota bar shows "{used} of {quota} used" for the user's own uploads. Starred GIFs do not count against the quota.

ST-22Add accepts several .gif, .webp or short video files at once, up to 50 MB each. The files go into the open folder. A progress line shows, and one error line shows for each refused file. Import accepts one zip up to the configured size (1 GB by default). The zip can have at most 1000 files of 50 MB each. Its subfolders become folders. When it has a tag list, the tag list adds tags. Export downloads the pool as a zip that imports back without loss, except starred provider GIFs that the server never stored.

ST-23Cards show newest first. They refresh at once when a star or an upload elsewhere changes the pool. A card shows the preview, up to four tag chips and the folder choice. The user edits tags in place. Tags are converted to lowercase. Each tag has 2 to 64 characters. Tags belong to the GIF, so a change affects search for everyone who can see the GIF. The user creates a new folder from the folder choice, with a name of up to 64 characters. A folder disappears when it no longer holds a GIF.

ST-24"Delete" on one of the user's own uploads asks "Sure?" before it deletes the file. When the file is still used in chat or by others, it is removed from the pool instead. It still counts against the quota while it exists. "✕" removes the star at once. Six cards show first, then 24 more for each tap.

App version

ST-28The App version card shows the build this device runs and, when the server runs a newer one, the server's build and a note. "Reload the app" fetches the page from the server, so the device gets the server's build even when the device keeps an old copy of the app, and the person lands back on Settings.

Debug

ST-25DEBUG INFO is a collapsed card. It shows what the browser keeps for Yap on this device: cached files by group with their size, and the storage estimate. It also has "Clear this cache" for the media cache. Clearing keeps drafts and unsent messages. Below the caches it lists the emoji images of this page load with the time each was asked for and answered, whether the service worker was in the path and whether a cache answered (the diagnostic for the cold-open wait). "Copy timings" puts the same numbers on the clipboard as text. <!-- lint: allow -->

Phones

ST-26At 600 px or less, the avatar is above its buttons. The notification rows stack, with full-width controls and 44 px buttons. The three choices of a row share one line on a 375 px phone at every text size. A 320 px phone at the largest text size wraps them. In a device list, the Remove button is under the device's text, at the right. The link controls wrap. The GIF grid has two columns.
